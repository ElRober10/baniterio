# Precio bebidas — Bebidas alcohólicas (rejilla marca × tienda) — Diseño

**Fecha:** 2026-09-17
**Rama:** `desarrollo`
**Contexto:** amplía la sección "Precio bebidas" (navegación años → eventos ya
hecha, commit `c4c9681`). Dentro de la pantalla de un evento, un botón
"Bebidas alcohólicas" lleva a una rejilla para ir apuntando el precio de cada
marca en cada tienda mientras se compara dónde comprar.

## Objetivo

Para un evento concreto: una tabla con una fila por marca de alcohol del
catálogo (Barceló, Ballantine's, Seagram's, JB...) y una columna por tienda
(Alcampo, Makro, Carrefour, Mercadona, Hipercor, Amazon, Merkocash...), con el
precio de esa marca en esa tienda en cada celda. Encima, una fila de pestañas
de tamaño (70 cl / 1 L por defecto) — la tabla es una por tamaño, y cambiar de
pestaña cambia los precios que se ven, no las marcas ni las tiendas. Se puede
añadir una pestaña de tamaño suelta (p. ej. "3 L") cuando ese evento sale una
botella grande a buen precio; y se puede añadir una tienda nueva al catálogo
en cualquier momento.

## Decisiones tomadas (brainstorming 2026-09-17)

- **Filas = catálogo de bebida existente**, no una lista aparte: exactamente
  las `Bebida` con `tipo = ALCOHOL` y `estado = ACEPTADA`
  (`BebidaRepository.findByTipoAndEstadoOrderByNombreAsc`). Si se acepta una
  bebida nueva, aparece sola en la rejilla del siguiente evento.
- **Tiendas: catálogo editable de la peña**, no una lista fija en código.
  Sembrado con Alcampo, Makro, Carrefour, Mercadona, Hipercor, Amazon,
  Merkocash. Cualquiera las ve; solo el admin añade nuevas. **v1 no permite
  borrar tiendas** (se puede añadir más adelante si hace falta).
- **Tamaños: pestañas compartidas por todo el evento**, no por marca. Se
  materializan con "70 cl" y "1 L" la primera vez que se abre la rejilla de
  ese evento (mismo patrón que `ReglaCompraEvento`); el admin puede añadir una
  pestaña suelta más. Añadir una pestaña la deja vacía para todas las marcas;
  no hace falta rellenar ninguna celda a la vez.
- **Celda = precio o vacío.** Solo se guarda fila en BBDD cuando hay un precio
  metido (`precio_bebida_evento`); vaciar una celda borra esa fila. La rejilla
  se construye cruzando marcas × tienda para el tamaño activo y rellenando lo
  que haya.
- **Permiso: todos ven, solo el admin edita.** "Admin" = administrador de
  verdad (`ServicioPermisos.esAdministrador`, rol ADMIN o superadmin), **no**
  un área concedida — mismo patrón que "Bebidas propuestas" / "Confirmar
  pagos" (`SinPermisoException`, `com.baniterio.api.admin`).
- **Sin cantidades ni "mejor precio" en v1.** Solo el precio por botella; sin
  resaltar la celda más barata (se puede añadir después si hace falta).
- Cerveza y refrescos tendrán su propio botón/pantalla más adelante,
  reutilizando el mismo catálogo de tiendas; **fuera de este spec**.

## Global Constraints

Igual que el resto de la app (ver specs anteriores): Java 17, Spring Boot,
Flyway (Postgres), Lombok, JUnit 5 + `RestTestClient` para IT. Angular
standalone + signals + control flow, Vitest. `environment.apiBaseUrl` =
`/api/v1`. Textos de UI en español. Errores de dominio → `{ "codigo": "<CODE>" }`
vía `ApiExceptionHandler`. Móvil **fuera de alcance** de esta tarea (se hará
aparte, a petición del usuario).

## Modelo de datos

### Tabla `tienda` (migración `V50__precio_bebidas_alcohol.sql`)

```sql
CREATE TABLE tienda (
    id      BIGINT      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    pena_id BIGINT      NOT NULL REFERENCES pena (id),
    nombre  VARCHAR(80) NOT NULL,
    orden   INT         NOT NULL DEFAULT 0,
    CONSTRAINT uq_tienda_pena_nombre UNIQUE (pena_id, nombre)
);
CREATE INDEX ix_tienda_pena ON tienda (pena_id);

INSERT INTO tienda (pena_id, nombre, orden)
SELECT p.id, v.nombre, v.orden
FROM pena p
CROSS JOIN (VALUES
    ('Alcampo', 1), ('Makro', 2), ('Carrefour', 3), ('Mercadona', 4),
    ('Hipercor', 5), ('Amazon', 6), ('Merkocash', 7)
) AS v(nombre, orden);
```

### Tabla `tamano_precio_bebida_evento` (misma migración)

Pestañas de tamaño de un evento; sin siembra (se materializa en el servicio).

```sql
CREATE TABLE tamano_precio_bebida_evento (
    id        BIGINT      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    evento_id BIGINT      NOT NULL REFERENCES evento (id) ON DELETE CASCADE,
    tamano    VARCHAR(20) NOT NULL,
    orden     INT         NOT NULL DEFAULT 0,
    CONSTRAINT uq_tamano_precio_bebida_evento UNIQUE (evento_id, tamano)
);
CREATE INDEX ix_tamano_precio_bebida_evento_evento ON tamano_precio_bebida_evento (evento_id);
```

### Tabla `precio_bebida_evento` (misma migración)

```sql
CREATE TABLE precio_bebida_evento (
    id        BIGINT        GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    evento_id BIGINT        NOT NULL REFERENCES evento (id) ON DELETE CASCADE,
    bebida_id BIGINT        NOT NULL REFERENCES bebida (id),
    tamano    VARCHAR(20)   NOT NULL,
    tienda_id BIGINT        NOT NULL REFERENCES tienda (id) ON DELETE CASCADE,
    precio    NUMERIC(8, 2) NOT NULL,
    CONSTRAINT ck_precio_bebida_evento_precio CHECK (precio >= 0),
    CONSTRAINT uq_precio_bebida_evento UNIQUE (evento_id, bebida_id, tamano, tienda_id)
);
CREATE INDEX ix_precio_bebida_evento_evento ON precio_bebida_evento (evento_id);
```

`ON DELETE CASCADE` en `tienda_id`: si algún día se borra una tienda (fuera de
v1, pero deja la puerta abierta), sus precios se van con ella.

### Entidades

Mismo patrón JPA + Lombok que el resto (`@Entity @Getter @Setter
@NoArgsConstructor @AllArgsConstructor @Builder`), en el paquete
`com.baniterio.api.preciobebida`:

- `Tienda`: id, `pena` (`@ManyToOne`), nombre, orden.
- `TamanoPrecioBebidaEvento`: id, `evento` (`@ManyToOne`), tamano, orden.
- `PrecioBebidaEvento`: id, `evento` (`@ManyToOne`), `bebida` (`@ManyToOne`,
  del paquete `identidad`), tamano, `tienda` (`@ManyToOne`), precio
  (`BigDecimal`).

## API

Todo en `PrecioBebidaController` / `PrecioBebidaService`
(`com.baniterio.api.preciobebida`), que ya existen (endpoint de años→eventos).

### `GET /api/v1/precio-bebida/tiendas`

Cualquier miembro logueado. `List<TiendaDto>` (`record TiendaDto(Long id,
String nombre)`), ordenadas por `orden`.

### `POST /api/v1/precio-bebida/tiendas`

Solo admin (`SinPermisoException` si no). Body `record CrearTiendaRequest(@NotBlank String nombre)`.
Recorta espacios; si ya existe (mismo nombre, sin distinguir mayúsculas) →
409 `TIENDA_DUPLICADA`. Si no, crea con `orden = max(orden de la peña) + 1` y
devuelve `TiendaDto` (201).

### `GET /api/v1/precio-bebida/eventos/{eventoId}/alcohol`

Cualquier miembro logueado. Materializa las pestañas de tamaño del evento
(70 cl + 1 L) si `tamanoPrecioBebidaEventoRepository.existsByEventoId` es
`false`. 404 `EVENTO_NO_ENCONTRADO` si el evento no existe / está oculto / es
de otra peña (reutiliza el patrón `eventoAbierto` ya usado en
`ListaCompraService`).

```json
{
  "puedoEditar": true,
  "tiendas": [{ "id": 1, "nombre": "Alcampo" }],
  "tamanos": ["70 cl", "1 L"],
  "bebidas": [{ "id": 5, "nombre": "Barceló" }],
  "precios": [{ "bebidaId": 5, "tamano": "70 cl", "tiendaId": 1, "precio": 8.5 }]
}
```

- `puedoEditar` = `permisos.esAdministrador(usuarioId)`.
- `bebidas`: reutiliza `BebidaRef` (`com.baniterio.api.evento.dto`, ya existe)
  vía `bebidaRepository.findByTipoAndEstadoOrderByNombreAsc(ALCOHOL, ACEPTADA)`.
- `precios`: **todas** las filas de `precio_bebida_evento` de ese evento (de
  cualquier tamaño); el front filtra por la pestaña activa. Así cambiar de
  pestaña no pide de nuevo al backend.
- DTO: `record PrecioCeldaDto(Long bebidaId, String tamano, Long tiendaId, BigDecimal precio)`,
  `record GrillaAlcoholResponse(boolean puedoEditar, List<TiendaDto> tiendas, List<String> tamanos, List<BebidaRef> bebidas, List<PrecioCeldaDto> precios)`.

### `PUT /api/v1/precio-bebida/eventos/{eventoId}/alcohol/precio`

Solo admin. Body:
`record GuardarPrecioRequest(@NotNull Long bebidaId, @NotBlank String tamano, @NotNull Long tiendaId, @PositiveOrZero BigDecimal precio)`
(`precio` nulo = borrar la celda, mismo patrón que `cantidadAjustada` en
`AjustarReglaRequest`).

1. 403 `SinPermisoException` si no es admin.
2. 404 `EVENTO_NO_ENCONTRADO` si el evento no es válido.
3. 404 `BEBIDA_NO_ENCONTRADA` si `bebidaId` no existe o no es `ALCOHOL`/`ACEPTADA`.
4. 404 `TIENDA_NO_ENCONTRADA` si `tiendaId` no existe o no es de esta peña.
5. 400 `TAMANO_PRECIO_BEBIDA_NO_VALIDO` si `tamano` no es una de las pestañas
   ya materializadas de este evento (se crean con el endpoint de abajo, no
   aquí).
6. Busca la fila por la clave única: si `precio` es `null` y existe, la
   borra; si `precio` no es `null`, hace upsert (crea o actualiza).
7. `204 No Content`.

### `POST /api/v1/precio-bebida/eventos/{eventoId}/alcohol/tamanos`

Solo admin. Body `record AnadirTamanoRequest(@NotBlank String tamano)`.
Recorta espacios; si ya existe esa pestaña en el evento (sin distinguir
mayúsculas) → 409 `TAMANO_PRECIO_BEBIDA_DUPLICADO`. Si no, `orden = max(orden
del evento) + 1`, guarda y devuelve `201` con la lista de tamaños actualizada
(`List<String>`) para que el front no tenga que recargar toda la rejilla.

### Excepciones nuevas

| Excepción | HTTP | codigo |
|---|---|---|
| `TiendaDuplicadaException` | 409 | `TIENDA_DUPLICADA` |
| `TiendaNoEncontradaException` | 404 | `TIENDA_NO_ENCONTRADA` |
| `TamanoPrecioBebidaDuplicadoException` | 409 | `TAMANO_PRECIO_BEBIDA_DUPLICADO` |
| `TamanoPrecioBebidaNoValidoException` | 400 | `TAMANO_PRECIO_BEBIDA_NO_VALIDO` |

`SinPermisoException` (`com.baniterio.api.admin`), `EventoNoEncontradoException`
y `BebidaNoEncontradaException` (`com.baniterio.api.evento`, código
`BEBIDA_NO_ENCONTRADA`) ya existen y ya tienen handler; reutilizar.

### Pantalla del evento (`precio-bebida-evento`)

Sustituye el placeholder "Próximamente" por un botón "Bebidas alcohólicas"
→ `[routerLink]="['/panel/precio-bebidas', anio, eventoId, 'alcohol']"`.

### Pantalla nueva `precio-bebida-alcohol` (`front/src/app/panel/precio-bebidas/alcohol/`)

- Ruta: `precio-bebidas/:anio/:id/alcohol`, `canActivate: [perfilCompletoGuard]`.
- `ngOnInit`: pide `alcohol(eventoId)`. Guarda `puedoEditar`, `tiendas`,
  `tamanos` (signal), `bebidas`, `precios` (signal `Map` o array).
- `tamanoActivo` (signal, por defecto `tamanos()[0]`). Pestañas: un botón por
  tamaño (resaltado el activo) + botón "+ Tamaño" (solo si `puedoEditar`) que
  pide el nombre con `prompt()` (mismo patrón sencillo que otros "añadir" de
  la app) y llama `anadirTamano`, luego añade la pestaña sin recargar toda la
  rejilla.
- Tabla: filas = `bebidas()`, columnas = `tiendas()`. Celda = el precio de
  `precios()` que cruce `(bebidaId, tamanoActivo(), tiendaId)`, o vacío. Si
  `puedoEditar()`, celda editable (`<input type="number">`, guarda al
  `blur`/Enter llamando `guardarPrecio`; vaciar el campo manda `precio: null`).
  Si no, texto plano.
- Bajo la tabla (o en la cabecera), si `puedoEditar()`: "+ Añadir tienda"
  (`prompt()` + `crearTienda`, luego recarga `tiendas()`).
- `<app-volver [destino]="'/panel/precio-bebidas/' + anio + '/' + eventoId" etiqueta="Evento" />`.

## Tests

### Backend

- `TiendaIT` (o dentro de `PrecioBebidaIT`): `GET /tiendas` lista las
  sembradas; `POST /tiendas` sin admin → 403; con admin crea; nombre
  duplicado → 409.
- `PrecioBebidaIT` (ampliar):
  - `GET /eventos/{id}/alcohol` materializa 70cl+1L la primera vez y los
    sigue devolviendo en la siguiente llamada (no duplica).
  - `bebidas` viene del catálogo `ALCOHOL`/`ACEPTADA`.
  - `PUT .../precio` sin admin → 403; guarda y se refleja en el siguiente
    `GET`; `precio: null` borra la celda; `tamano` que no es una pestaña del
    evento → 400 `TAMANO_PRECIO_BEBIDA_NO_VALIDO`; `bebidaId`/`tiendaId`
    inexistente → 404.
  - `POST .../tamanos` sin admin → 403; añade pestaña; repetida → 409.

### Web (Vitest)

- `precio-bebida.service.spec.ts`: los 5 métodos nuevos (método + URL + body).
- `precio-bebida-alcohol.spec.ts`: pinta filas × columnas; cambia de pestaña
  y se ven otros precios sin nueva petición GET; sin `puedoEditar` las celdas
  no son editables; con `puedoEditar`, escribir un precio hace el `PUT`;
  "+ Tamaño" y "+ Añadir tienda" llaman a lo suyo.
- `precio-bebida-evento.spec.ts`: el botón "Bebidas alcohólicas" enlaza a la
  ruta `alcohol`.

## Orden de implementación sugerido (para el plan)

1. Backend: migración V50 (`tienda` + `tamano_precio_bebida_evento` +
   `precio_bebida_evento`) + entidades + repos + excepciones.
2. Backend: `GET/POST /precio-bebida/tiendas` + IT.
3. Backend: `GET /eventos/{id}/alcohol` (con materialización) + IT.
4. Backend: `PUT .../precio` + `POST .../tamanos` + IT.
5. Web: tipos + servicio + specs del servicio.
6. Web: pantalla `precio-bebida-alcohol` (rejilla + pestañas + añadir tienda)
   + specs; botón desde la pantalla del evento.

## Fuera de alcance (v1)

- Móvil (tarea aparte, a petición del usuario).
- Borrar tiendas.
- Resaltar el precio más barato de cada fila.
- Cantidades / cuánto comprar en cada tienda (eso lo cubre la lista de la
  compra, sección aparte).
- Cerveza y refrescos (mismo patrón, pero en otra tarea).
